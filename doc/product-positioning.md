# 产品定位

状态：产品方向文档，用于约束功能取舍；不是接口契约，也不代表所有能力已实现。

## 一句话定位

> 引序是一个通用的慢节奏行动对话平台：用户记录自己真正做过的事，写下希望得到的回应约定，等待另一个人用一次认真的行动接住。

聊天的最小单位不是一句即时消息，而是一条**行动**。

平台不限定领域。游戏、学习、工作、创作、运动、生活实践都可以使用；当前用游戏案例做验证，是因为游戏过程容易描述细节和结果，不代表平台只服务游戏。

## 目标用户

- 对少数领域有持续投入的人；
- 愿意复盘过程、细节、取舍和变化的人；
- 愿意写细节、看长文、等待回复的人；
- 更在意“有人认真回应我的行动”，而不是点赞和播放量的人。

典型场景：

- 一次练习、实验或项目复盘；
- 一次创作、建造或研究过程；
- 一次旅行、运动、烹饪或生活实践；
- 游戏战役、路线和机制研究；
- 工作或学习中的一次尝试；
- 对某个版本、规则或方法的验证。

不是面向：

- 只看短视频和热闹内容的用户；
- 需要即时回复和强互动的用户；
- 把平台当资料仓库、新闻站或问答区的用户；
- 依靠点赞、排行和粉丝数获得反馈的流量创作者。

## 用户痛点

一个人认真做了一件事，认真写了下来，却通常得到：

- 一个点赞；
- 一句“厉害”；
- 与内容无关的玩梗；
- 或者没有任何回应。

平台要解决的不是“没有地方发内容”，而是：

> **认真付出的行动，能不能得到另一个人的认真回应。**

## 核心循环

```text
记录一次真实行动
  → 形成自己的表达
  → 写下希望别人怎样回应的约定
  → 其他人看到后承接约定
  → 对方实际去做，再记录自己的行动
  → 核对是否满足来源约定
  → 形成新的行动节点
```

在这个循环里：

- 行动是事实；
- 表达是态度；
- 约定是回复邀请；
- 回复不是评论，而是一条新的行动；
- 图是对话的历史，不是信息流。

## 产品原则

### 1. 行动是核心对象

不是“发帖 + 评论”，而是“用行动回复行动”。

回复必须能说明：

- 我实际做了什么；
- 我和来源行动是什么关系；
- 我是否满足了对方的约定；
- 我自己的判断和感受是什么。

### 2. 约定是邀请，不是审批

约定回答的是：

- 你希望对方记录什么？
- 你希望对方从哪个角度回应？
- 你希望对方验证什么？

约定不应该变成：

- 发布审批；
- 作者同意；
- 平台打分；
- 复杂合同；
- 强制回复。

约定可以没有；有约定时也应该轻量、具体、可判断。

### 3. 慢，不等于难用

慢节奏减少的是：

- 即时回复压力；
- 流量竞争；
- 无意义互动；
- 算法刺激。

不应该增加的是：

- 复杂表单；
- 反复核验；
- 审核等待；
- 为了“仪式感”制造的操作步骤。

AI 的作用是降低表达成本，不是增加流程。

### 4. 不做流量思维

不优先做：

- 点赞数、浏览量、粉丝排名；
- 热门榜、推荐流、连续签到；
- 无限下拉和强推送；
- 用高刺激内容换停留时长。

优先做：

- 按领域、主题和背景浏览；
- 关注具体的人和行动链；
- 明确的回复请求；
- 行动链和来源关系；
- 低频、批量通知。

### 5. 深度不等于精英化

鼓励细节和研究，但不使用：

- 等级或身份门槛；
- 粉丝数门槛；
- 资历门槛；
- 榜单排名。

判断内容的标准是：是否认真、是否可回应、是否来自真实行动。

## 产品不是什么

- 不是新闻站或资料仓库；
- 不是短视频高光平台；
- 不是问答区；
- 不是即时聊天室；
- 不是靠点赞和排行驱动的内容社区；
- 不是用 AI 代替用户编造经历的工具。

## 关键术语

| 术语 | 含义 |
| --- | --- |
| 行动 | 一次已经发生的真实经历，不包含计划、目标和完成状态 |
| 表达 | 基于行动形成的兴趣、态度、判断或想继续讨论的问题 |
| 约定 | 希望后来引用者怎样回应的条件 |
| 承接 | 引用一个已有节点，并继续自己的行动 |
| 约定核对 | 判断自己的行动是否满足来源节点的约定 |
| 形成过程 | AI 对话和草稿如何形成这次行动，可对作者可见、对其他人隐藏 |

## 成功指标

不把日活、使用时长和点赞作为北极星指标。

更合适的指标：

- 每周完成的、满足来源约定的认真回复数；
- 每条行动收到认真回复的比例；
- 回复中包含实际动作而不是只有评论的比例；
- 同一对用户形成多次行动往来的比例；
- 30 天回访；
- 每个主题下有效行动链的数量。

北极星指标建议：

> **每周完成的、满足来源约定的认真回复数。**

## 冷启动与运营

慢平台最怕空房间，不能只靠推荐流起量。

建议：

- 先做一个具体主题、领域或一群人；
- 邀请 20～50 个愿意认真复盘的人；
- 游戏可以作为首批主题之一，但不是平台边界；
- 人工组织第一批“行动—约定—回复”；
- 让新用户第一次进入就能看到一个正在等待回复的具体约定；
- 不追求内容数量，先追求每个行动都能被认真接住。

## 主要风险

1. **门槛太高**：约定、核验和 AI 流程过重，用户不愿意写第二次。
2. **空场**：没有足够多愿意回复的人，行动链断掉。
3. **深度变成排外**：用资历和圈层排斥新用户。
4. **流量化**：为了增长加入点赞、热门和强推送，偏离慢节奏定位。
5. **隐私与可追溯冲突**：作者需要更正和隐藏，但行动链又需要稳定上下文。
6. **AI 过度介入**：AI 代替用户编造行动，或者核验变成审批。

## 当前取舍

- 行动记录优先真实、可回溯；
- 表达优先兴趣、态度和可讨论性，而不是行动摘要；
- 约定优先具体、可判断，而不是强制审批；
- 核验是帮助，不是发布门槛；
- 形成过程可以隐藏，公开页面只展示当前内容；
- 平台优先深度和回应质量，不优先流量和刺激。

## 验证定位是否成立

用一组真实行动测试，至少包含游戏之外的场景：

1. 用户是否愿意写出足够具体的行动；
2. AI 是否能把它整理成“我做了什么”；
3. 其他用户是否能看懂并愿意承接；
4. 约定是否真的帮助回复变得认真；
5. 用户是否愿意再写第二次；
6. 回复是否比普通评论区更有内容。

如果用户只愿意看、不愿意回复，或者回复仍然是一句“厉害”，说明定位还没有真正成立。
