# 行动图页面 UI 设计

本文记录行动图页面当前确定的网页端展示逻辑。它是产品设计文档，不描述代码结构，也不代表当前页面已经完全按此实现。

## 1. 页面定位

行动图用于公开记录持续发生的行动，以及这些行动如何连接成主线和支链。发起者只是创建起点；符合来源节点约定的人都可以接续，不由发起者控制后续行动。行动图不是任务清单，也不要求用户先设定目标再提交结果。

用户进入行动图后，需要理解三件事：

```text
最近发生了哪些行动
这些行动如何连接成主线和支链
不同的人正在沿着哪些路线继续行动
```

页面采用行动关系工作区：左侧是固定宽度、纵向延伸的纯节点图，右侧阅读当前选中节点的行动记录，或当前选中连线的引用详情。不再采用 Git 历史中图轨道与标题列表逐行对齐的布局。

行动图头部只承担图的身份识别：图头像、标题和简介。参与人、帖子、行动节点和最近更新在帖子列表右侧的“图信息”栏展示，避免重复占用顶部介绍区域。参与人按发布过行动节点的用户去重；帖子按行动路线当前终点计算，同一路线的后续节点不重复计数；行动节点是图中的全部节点；最近更新取最新行动节点的发布时间。没有行动节点时，最近更新时间回退到行动图创建时间。

行动图使用固定的贴吧式内容导航：`精华`、`热门`、`最新`、`探索图`。四个入口从图创建时就存在，不根据内容数量隐藏。前三个入口展示帖子列表；没有帖子时显示空状态。`探索图`进入节点关系工作区，即使还没有帖子，只要存在起始节点也可以使用。

帖子是一条行动路线当前终点形成的公开表达，不是单个节点。沿同一路线继续行动时，原帖子更新到新的终点；从中间节点分出的路线形成新的帖子；合入多个来源的终点仍然是一个帖子。帖子列表默认显示终点节点的标题、行动表达摘要、作者、路线节点数、参与人数、更新时间和图片。点击帖子后进入探索图，并将该帖子的完整引用路径作为当前主链，右侧默认打开终点节点的行动表达；“定位主链”回到这条路径的终点。

```text
图头像、行动图名称、图简介
固定导航：精华、热门、最新、探索图
帖子列表右侧：图信息

┌───────────────┬──────────────────────────────┐
│ 节点关系        │ 当前节点详情                  │
│               │                              │
│ ●             │ 节点 #10 · 主线                │
│ │             │ 把做菜记录带回家                │
│ ●──●          │ 作者、时间、行动记录、图片        │
│ │   ╲         │                              │
│ ●    ●        │ 查看形成过程 · 沿此记录 · 另开支链 │
│ │             │                              │
│ ●             │                              │
└───────────────┴──────────────────────────────┘
```

点击节点查看行动文档，点击连线查看引用关系详情，两者共用右侧阅读区域。

## 2. 节点图

### 2.1 节点代表一次行动记录

每个节点只代表用户真实发生的一次行动记录。行动可以是尝试、复做、调整、失败、部分结果或新的观察，只要用户愿意记录，就可以成为节点。系统不要求行动对应某个目标，也不判断行动是否“完成”。

用户可以先行动，再与 AI 对话，把行动经过、结果和观察整理成一份记录，最后决定是否发布为节点。AI 对话是记录的形成过程，节点是公开可阅读的行动结果。

节点编号使用行动图内稳定的 `节点 #N`：按节点创建顺序分配，节点进入主线或支链后都不重新编号，也不会因为主线排序变化而改变。主线/支链是节点的关系属性，编号是节点本身的身份。

圆点里的数字表示层级，不是节点编号。起始节点为第 1 层，后续节点为所有直接引用来源中最深层级加 1。同一层可以有多个节点；多来源引用不累加各条路线的节点数量。悬浮信息同时显示层级和稳定编号，编号继续用于唯一定位。

### 2.2 固定宽度的纯节点图

左侧采用 Cytoscape + Dagre 的纵向图，图宽固定为 340px。节点圆点只显示层级数字，标题、稳定编号、作者、摘要和约定在悬浮时显示，不保留旁边逐行对齐的标题列表。

引用来源位于后续行动下方，较新的行动在上方；不同分支可以共享高度，不要求一个节点占一整行。图增加时向下延伸，不将全部历史缩进可视区域。

```text
      7         7
     / ×      /  ╲
    6        6     3
      ╲     /      │
         5        2
```

图形含义分别定义，不互相替代：

- 圆点代表一次行动；箭头由来源行动指向后续引用它的行动。
- 实线表示来源作者与新节点作者相同；虚线表示不同作者之间的引用，与当前浏览者身份无关。
- 不满足来源约定时，在线上显示叉号。符合约定时不增加标记；缺少核对结果时不能假装符合，悬浮时说明。
- 叉号表示不满足原约定，不表示拒绝授权。自己引用自己的例外自动同意；跨作者例外需要来源作者同意，获准后仍保留叉号。
- 主线使用绿色，其他路线使用较弱的颜色。选中状态用外圈强调，点击支链不会改变主线。
- 承接与合入都保留真实连接，二者在连线悬浮信息中说明，不再通过实线与虚线区分。
- 选中时强调当前节点及全部引用来源历史；其他路线降低对比度但不消失，点击不重新布局。

主线算法只决定默认强调和选中哪条路线，不改变节点身份。未从帖子进入探索图时，原型用最长主要承接路径作为默认强调；从帖子进入探索图时，优先强调该帖子的完整引用路径。正式的竞争算法尚未确定。

### 2.3 长支链的折叠

长链不能把所有支链节点一次性铺开。折叠时保留分叉起点、最近节点、当前选中节点和必要的汇合点，中间使用一行关系提示：

```text
● 节点 #20
│
⋮ 支链 A 中间还有 18 个行动
│
● 节点 #39
```

折叠提示本身属于图轨道的一部分，点击后展开这一段节点。支链数量、最近行动时间和参与者可以作为提示信息显示，但不能把支链改写成待完成的方案。

进入探索图时默认选中当前主链终点。用户点击某个支链节点后，历史图保留其他路线，强调选中节点及其来源上下文，并在当前节点附近展开必要的历史。

当前 frontend-v2 使用 Cytoscape + Dagre，显示行动图已提供的行动数据。长支链折叠和分批加载尚未实现，不能靠压缩横向位置长期容纳无限分支。番茄炒蛋的 #13、#14 演示多来源引用，#10 → #13 演示自己引用自己的约定例外，#3 → #6 演示获得来源作者同意的跨作者例外。

### 2.4 悬浮信息

悬浮或键盘聚焦节点时显示：

- 节点层级、稳定编号与行动标题。
- 作者头像、用户名、时间。
- 最多三行的客观行动摘要，以及可选的一张缩略图。
- 引用链包含的历史行动数量，和当前节点设置的引用约定。

悬浮或键盘聚焦连线时显示双方节点编号、作者、承接或合入关系、来源约定、核对结果，以及例外原因和授权状态。悬浮信息不替代右侧完整文档。

### 2.5 节点操作

- 点击节点：右侧切换到该节点。
- 点击连线：持续高亮该引用，右侧显示引用双方、完整来源约定、核对结果、例外原因与授权状态。点击双方节点卡片可返回对应文档，也支持 Enter 或空格选择连线。
- 点击支链节点：保留图中其他轨道，右侧显示该行动记录。
- 点击顶部“定位主链”：选中当前帖子主链终点并滚动到可见位置；没有从帖子进入时定位默认主链终点，即使已选中该节点，也可以再次定位。
- 点击“沿此继续”：以当前节点为上下文，开始记录下一次行动。
- 已有行动的行动图不在页头提供无上级的记录入口，用户需从具体节点继续记录。
- 点击“另开方案”：从当前节点建立一条新的支链，然后记录行动。
- 按节点编号定位、长支链折叠作为后续功能。

### 2.6 引用背景与本次实现边界

新节点的已知历史执行事实仅来自直接引用节点以及沿全部引用关系追溯到起始节点的历史。多来源取并集并去重，不包含同一行动图里未引用的其他分支，也不能用“编号减一”计算历史数量。历史观点仍然是观点，不能当作已验证事实；本次行动另由用户提供新增事实。

约定可申请例外，但例外不会扩展历史事实范围。想纳入另一条路线的执行事实，需要增加引用。

本次实现节点图、悬浮信息、引用关系详情和样例数据中的约定状态展示。约定编辑、申请审批、发布校验和 AI 事实背景约束仍属于后续功能；示例授权不代表已接入真实审批系统。

## 3. 右侧节点详情

选中节点时，右侧展示其两份行动记录之一。它不使用“摘要 / 详情”切换，因为摘要和详情不是两个业务状态；默认展示客观行动记录，需要理解这次行动如何形成观点时再切换到行动表达，需要追溯时进入形成过程。选中连线时，此处切换为引用关系详情。

界面入口简化为“记录”和“表达”两个普通文字按钮，不使用带底色、边框或阴影的分段控件。当前项以主题绿色显示，另一项为灰色；按钮只切换当前节点的文档。

### 3.1 节点头部

```text
节点 #4 · 主线
整理出自己的番茄炒蛋原则
jo · 10/11 20:05 · 2 条后续行动 · 2 条支链
```

头部说明节点编号、主线/支链位置、行动记录标题、作者、时间和后续关系。不额外生成一个需要别人总结的标题。

作者信息保持单行紧凑排列：24px 头像、12px 用户名、11px 灰色日期，垂直居中。头像与用户名间距为 8px，日期与作者组间隔略大；缺少头像时使用用户名首字。用户名较长时省略，空间不足时日期可换行。

### 3.2 默认内容

其他用户默认看到行动记录：

```text
头像  用户名  时间

这次把番茄先炒到出汁，再加入蛋液。两次复做都控制在 20 分钟内，第二次减少了调味步骤，出锅后更接近想要的酸甜味。

图片缩略图

留下的观察：火候变化比调味先后更影响口感。

查看形成过程   查看 AI 对话   沿此继续   另开方案
```

公开内容默认由行动经过、实际结果和行动者留下的观察组成。节点可以没有图片，也可以包含多张图片；图片只在实际存在时显示。右侧提供两份记录的切换：客观行动记录只描述本次发生的事实，行动表达基于本次行动和历史上下文形成观点、判断与偏好。

“查看形成过程”进入独立资料页，展示这条记录从原始行动描述到公开 Markdown 的整理过程；“查看 AI 对话”展示形成这条记录的连续对话历史。两者都属于同一条行动记录的上下文，不再拆成彼此独立的内容。

### 3.3 一个节点中的内容

一个节点对应一条行动记录，不再把多条行动强行合并，也不再把一次行动拆成两种内容。记录可以包括：

- 行动标题或首句。
- 行动者、时间和可选地点等基本信息。
- 实际做了什么，以及过程中的关键变化。
- 行动产生的结果、失败或部分结果。
- 行动者留下的观察、判断或下一步想法。
- 图片等行动证据。
- 用于形成记录的 AI 对话和 Markdown 历史。

如果用户连续做了两次行动，应发布为两个节点；后一个节点通过接续关系连接前一个节点。这样每个节点都保持清楚的时间和行动边界，也让主线和支链能够反映真实的行动路线。

### 3.4 两份记录与行动图指引

每个节点保存两份由 AI 对话整理出的 Markdown 文档：

- **客观行动记录**：只记录当前行动实际发生了什么、结果、证据、失败和观察。它是默认公开内容，不能为了符合某种观点改写事实。
- **行动表达**：基于当前行动和之前节点形成的观点、判断、偏好或方法。它不是对事实的替代，也不要求每次行动都产生新的结论。

行动图可以设置可选的**行动图指引**（技术上可称 persistent context instruction）。它是长期作用于行动图的 AI 对话背景，帮助后续节点保持关注重点，例如复做性、时间限制或事实与偏好的区分。没有指引时，用户可以自由表达；有指引时，指引只约束 AI 的提问和整理方向，不能要求用户把真实行动改写成符合指引的结果。指引不在行动图页头常驻展示；需要核对某次记录所用的指引时，可到形成过程查看。

查看行动表达时，顶部只展示有限的上下文摘要：直接引用节点、引用链历史节点数量、指引是否启用，以及合入来源。不展开完整历史节点列表。形成过程页可以展开同一份摘要，并查看本次 AI 对话。

## 4. 滚动与阅读

顶部显示图头像、行动图名称和图简介，与工作区左边缘对齐；返回按钮以绝对定位放在顶部详情卡左侧留白中，上边缘与详情卡上边缘对齐，不参与详情卡排版。使用无边框的左箭头，图标 18px、点击区域 32px，不常驻返回文字。拥有编辑权限的用户可在“探索图”Tab右侧通过带齿轮图标的“设置”Tab进入独立设置内容，用于编辑图形象与基本信息；设置与精华、热门、最新、探索图一样是同级页面，不使用弹窗，也不与其他 Tab 内容同时显示。图头像和背景图通过图片选择器上传，设置页提供预览、更换和移除，不要求用户填写图片 URL。当前原型以本地图片数据预览，接入对象存储后由上传服务返回资源地址。帖子列表视图的参与人、帖子、行动节点和最近更新时间集中放在右侧“图信息”栏。设置权限由图的编辑权限决定。悬浮或键盘聚焦返回按钮时显示具体返回去向；从“我的”进入则返回“我的”，从“所有行动图”进入则返回列表。切换节点与引用不会改变页面返回目标。

页面采用固定职责的双栏工作区：

- 节点图和右侧详情组成一个整体，高度为当前浏览器可视区域高度，并随窗口尺寸变化自动适配，不再限制最大高度。
- 图身份栏在工作区上方，工作区下方不额外留白；页面滚动到底时，工作区上下边缘正好与可视区域贴合。
- 图顶部提供仅显示图标的“重新铺满”按钮，将整个工作区重新对齐窗口顶部；不进入浏览器全屏，不改变选中对象或两栏内部阅读位置。
- 左侧只浏览节点关系。
- 右侧显示当前选中对象的详情：节点对应行动记录，连线对应引用关系。
- 点击连线后，右侧展示引用双方、来源约定、约定核对结果、例外原因与授权状态，以及这条引用带入的历史背景数量。引用双方均可点击，返回对应节点文档。
- 连线选中后沿原路径加粗、略放大箭头，保留原有颜色、实虚线和叉号，不使用包围整条连线的矩形框。键盘焦点也沿路径提示；节点和连线互斥选中，切换不会改变主线。
- 行动图页头属于工作区上下文，不随着某个节点内容重复出现。
- 节点图和详情区各自只有一个滚动区域，不再叠加页面、卡片和列表的多层滚动。
- 精华、热门和最新使用主列表加右侧“图信息”栏的双栏布局；列表收窄，图信息栏固定展示参与人、帖子、行动节点和最近更新。探索图切换回节点图与右侧行动详情的双栏布局。
- 右侧滚动较深时，当前节点仍保持选中状态。
- 右侧选中对象切换后，滚动位置回到详情顶部。

这种滚动方式是 Git 历史浏览器式的明确双栏，而不是把多个内容流临时拼在一起。

## 5. 用户阅读路径

默认路径是：

```text
打开行动图
→ 先看“精华 / 热门 / 最新”中的帖子列表
→ 选择一条帖子，进入“探索图”并定位到这条帖子的主链终点
→ 阅读终点的行动表达，再按需切换到记录
→ 看左侧主链和分支，比较不同的实际行动路线
→ 需要追溯时查看记录形成过程或 AI 对话
→ 沿当前节点继续记录，或从这里另开一条支链
```

行动图刚创建、还没有帖子时，四个栏目仍然显示；前三个栏目显示各自的空状态，用户可以切到“探索图”查看起始节点。

## 6. 帖子简略信息规范

帖子列表是行动图的默认入口，采用贴吧式的简略卡；“探索图”才进入节点关系和右侧行动详情。简略卡用于判断一条行动路线值不值得打开，不替代完整记录。

### 6.1 简略卡内容

```text
节点编号 · 主线/支链
行动记录标题
头像 用户名 · 时间
行动摘要
图片缩略图
```

### 6.2 显示限制

- 标题最多 1 行，超出省略。
- 作者信息 1 行，头像与用户名同时显示。
- 行动摘要最多 3 行，超出省略。
- 图片最多显示 3 张缩略图。
- 没有图片时不保留图片区域。
- 默认显示行动摘要，不显示目标字段或状态提示。
- 简略卡不展示 AI 对话正文，只提供进入记录形成页的入口。

### 6.3 简略卡的使用原则

简略卡必须保持稳定高度、信息层级清楚，并避免把行动标题重复显示为额外的楼层标题。点击卡片后，帖子终点成为当前主链终点，右侧默认显示“表达”。

## 7. 默认界面与按需帮助

按熟练用户使用设计默认界面：直接展示内容、状态和操作，不常驻功能教程与机制解释。

- “节点关系”标题旁的问号收纳层级数字、连线、叉号、主线和浏览操作的详细解释。全局“设置 → 界面偏好”控制图例显示，默认隐藏；图例只列实线、虚线、叉号和节点内数字的含义，并记住本机浏览器中的选择。图设置只负责图形象和基本信息，不替代全局界面偏好。
- “记录 / 表达”旁的问号解释两份文档的区别、AI 整理方式及形成过程入口。
- 引用详情标题旁的问号解释作者关系、约定与例外授权规则、历史背景范围；正文只保留实际引用双方、约定、核对结果、例外原因、授权状态和背景数量。
- 形成过程页去掉重复的功能副标题，将说明集中在页头问号内。
- 问号点击后展开轻量帮助浮层，支持关闭按钮、点击外部或 Escape 关闭，并恢复键盘焦点。不在悬浮时自动弹出说明。
- 行动图简介、作者文档和来源约定属于实际内容；错误、待授权等状态属于操作依据，均不能作为说明文案隐藏。行动图指引不常驻页头，但可在相关记录的形成过程中查看。

## 8. 当前设计结论

行动图页面顶部只显示图身份，左侧采用固定宽度、纵向延伸的 Cytoscape 纯节点关系图，右侧显示选中节点的客观行动记录或行动表达。连线实虚区分作者是否相同，叉号表示不满足来源约定，主线颜色和选中外圈分别表达路线与阅读位置。创建行动图时，图标题和起始行动记录同时生成节点 #1；之后图设置中的标题、简介、头像和背景图属于可修改的图元信息，不回写节点 #1 的历史内容。行动图不要求预先设定目标，也不提供额外状态字段；每个节点只记录一次真实行动，但可以从事实记录和上下文表达两个角度阅读。AI 对话、两份 Markdown 和上下文快照通过按钮进入独立资料页查看。帖子简略信息规范保留给列表等场景，节点图只借用它的摘要显示限制来提供悬浮预览。
