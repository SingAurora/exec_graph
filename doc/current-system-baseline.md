# 当前系统基线

更新时间：2026-09-21

本文记录当前代码已经提供的产品和工程行为，用来区分“已实现能力”和“长期设计方向”。产品理念仍以 [产品逻辑设计](./product-logic-design.md) 和 [执行力逻辑递进](./execution-force-logic.md) 为准；界面目标和历史改造过程见 [前端重设计方案](./frontend-redesign-plan.md)。

## 1. 当前产品闭环

一次普通推进的基本流程是：

```text
选择项目与规则
-> AI 起草或审查节点草案
-> 用户确认冻结目标、验收标准和证据要求
-> 用户推进并提交实际行动、观察和材料
-> AI 按行动规则整理记录覆盖情况、未知信息和下一步
-> 用户确认当前现实状态，或继续观察、补充和创建下一步行动
-> 生成阶段完成记录
-> 从当前节点、完成记录或多个来源继续下一次推进
```

节点和完成记录是不同对象。节点记录实际推进，完成记录记录哪一组节点被一次用户确认覆盖。AI 的分析不等于现实完成证明；它只帮助用户把纸面目标、实际行动和现实反馈区分开。

当前节点阶段主要包括：

| 阶段 | 含义 |
| --- | --- |
| `frozen` | 目标、验收标准和证据要求已冻结，等待推进或提交 |
| `verified` | AI 审查通过，等待用户确认 |
| `needs_supplement` | 证据不足或目标未闭合，保留当前结果并等待补足 |
| `completed` | 已被完成记录覆盖 |

## 2. 项目与归档

- 新建项目可以选择规则模板、审查 AI 和公开/私有可见性。
- 项目描述可以为空；为空时前端不展示描述区域。
- 默认项目不再承担特殊业务流程。初始项目和用户新建项目都按普通项目处理。
- `isDefault` 仍是兼容字段，但不是项目选择、节点创建或工作总览的业务依据。
- 归档是可恢复的状态变更：归档后停止继续推进，但保留历史数据。
- 删除是独立的永久删除操作；项目存在外部成果采纳关系时禁止删除。
- 被外部项目采用的来源成果不能通过普通项目删除或改为私有，以保持关系可追溯。

## 3. 协作与执行网络

当前已实现的协作流程：

```text
公开项目冻结一个待推进节点
-> 发布开放缺口
-> 其他用户提交自己的公开已采纳成果
-> 目标项目维护者选择投稿
-> 使用目标项目规则进行 AI 组合审查
-> 维护者确认采纳或保留未采纳结果
```

探索页是公开入口，不要求登录浏览。当前执行网络从真实数据库事实生成，支持：

- 项目视角
- 人物视角
- 成果视角
- 维护关系
- 成果形成关系
- 正在贡献关系
- 正式采纳关系
- 贡献工作区关系
- 节点和关系点选详情

当前还没有独立的普通“引用成果”操作、基于成果继续操作、正式派生关系、时间回放、群落聚合和质量权重系统。前端类型中预留的 `reference` 等关系类型不代表后端已经提供对应业务流程。

## 4. 工作总览与日常行动

工作总览不是传统打卡或工时系统。当前提供：

- 按月份读取当天已经发生的行动记录
- 查看每天的节点推进、完成和锁定活动
- 对已有行动记录的某一天发起 AI 日结分析
- 保存摘要、推进状态、亮点、阻碍和下一步

日结 AI 只能分析当天已经保存的事实，不能证明现实结果、修改节点规则，也不能根据一天的记录评价用户人格。推进状态使用有限枚举：

```text
稳步推进 / 集中完成 / 起步探索 / 受阻待续
```

## 5. 鉴权与安全

- 登录后使用访问令牌调用需要认证的接口。
- 会话实际保存在 Redis，Redis 不可用时不会回退到 MySQL 会话。
- 数据库内部主键使用 MySQL 自增 ID。
- API 对外使用稳定 UUID，不暴露业务对象的内部自增 ID。
- 账号密码使用 bcrypt 哈希保存。
- AI Key 使用 AES-256-GCM 加密保存，API 只返回服务商、模型和掩码信息。
- 前端所有 HTTP 请求通过共享 API client，业务页面不直接调用 `fetch`。

## 6. HTTP 契约

路由由 `backend/internal/http/router` 统一维护：

- 读取使用 `GET`，筛选参数放 query。
- 创建、更新、审查和其他状态变化使用 `POST`，参数放 JSON。
- 上传使用 `POST multipart/form-data`。
- 不使用通配路径、路径参数、`PATCH` 或 `DELETE`。
- JSON 返回统一使用：

```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

错误在 HTTP 顶层错误边界统一转换，endpoint 不重复实现响应包装。

## 7. 后端分层

```text
backend/cmd
  进程启动入口
backend/internal/bootstrap
  配置读取和依赖组合根
backend/internal/application/<domain>
  用例、业务规则、事务边界和领域 DTO
backend/internal/infrastructure/persistence/<domain>
  GORM 模型、SQL 查询、事务和数据库适配
backend/internal/http/endpoint/<domain>
  请求绑定、认证用户提取、用例调用和响应映射
backend/internal/http/router
  唯一路由所有者
backend/internal/shared
  无业务归属的常量、ID 和错误能力
```

application 层不依赖 HTTP 或 GORM；SQL 和 GORM 只在 persistence 层出现；bootstrap 是创建基础设施和 application service 的唯一组合根。

## 8. 演示数据

公开探索网络的演示数据不会随 API 启动自动写入。需要时显式执行：

```bash
EXEC_GRAPH_ALLOW_DEMO_SEED=1 \
EXEC_GRAPH_DEMO_PASSWORD='本地测试密码' \
go run ./cmd/demo-seed -allow
```

命令位于 `backend/cmd/demo-seed`，持久化实现位于 `backend/internal/infrastructure/persistence/demo`。它只创建或更新带 `demo-` 标识的测试账号和演示数据，不删除普通用户数据，并且可以重复运行。

## 9. 后续明确规划

以下内容属于后续产品工作，不应当在当前文档中描述为已实现：

1. 普通成果引用和“基于此继续”。
2. 跨项目派生关系和成果网络的完整来源链。
3. 网络一度/二度展开、群落聚合、稳定布局和时间回放。
4. 通知、关注订阅、全局搜索和历史导出。
5. 基于有效接续、采纳和下游成果的质量权重与防刷规则。
