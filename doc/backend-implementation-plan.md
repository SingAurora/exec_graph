# 后端实施计划

本文件记录逐阶段交付边界和验证证据，不以建表或 mock 成功代替真实功能可用。

## 技术与目录

使用 Go 1.23、Gin、GORM、MySQL、Redis。表间通过 UUID 逻辑关联，不建外键。业务查询和写入使用 GORM；仅数据库创建、迁移锁和数据库元信息诊断等 GORM 无法表达的管理操作可使用明确限定的 SQL。不在请求路径自动迁移。

```text
backend/
  cmd/api/                         HTTP 进程启动
  cmd/manage/                      检查依赖、迁移、导入、验证命令
  etc/                            本地配置与无密钥示例
  internal/bootstrap/             配置、依赖创建和服务装配
  internal/application/
    identity/                     登录、会话、账户 DTO 与端口
    catalogue/                    当前前端的目录及行动上下文读取
    demoseed/                     演示导入输入校验与数据转换
    graph/                        图管理与删除规则
    action/                       行动发布与文档确认
    profile/                      资料与精选
    following/                    显式关注状态
    submission/                   创建命令的幂等重放
    generation/                   AI 生成与确认边界（后续阶段）
  internal/infrastructure/
    persistence/model/            GORM 模型，只有 UUID 逻辑关联
    persistence/schema/           有版本记录的 Go/GORM 迁移
    persistence/identity/          账户仓储
    persistence/catalogue/         目录与上下文读取仓储
    persistence/demoseed/          演示数据事务导入
    persistence/graph/             图管理事务仓储
    persistence/action/            行动及文档事务仓储
    persistence/profile/           资料及精选事务仓储
    persistence/following/         关注事务仓储
    persistence/transaction/       认证锁、资产检查及幂等记录
    session/                      Redis 会话与限流
    security/                     密码哈希、随机令牌
    mail/                         邮件客户端（后续阶段）
    storage/                      对象存储客户端（后续阶段）
    ai/                           平台 AI 客户端（后续阶段）
  internal/http/
    router/                       唯一的 URL、方法和分组定义
    endpoint/                     参数绑定及用例适配

  scripts/export-demo.ts          显式导出现有前端演示内容与图片

```

application 不依赖 Gin、GORM 或配置包；bootstrap 创建并注入所有外部客户端。旧代码仅参考外部依赖调用方式，不恢复旧计划、协作、个人 AI Key 等产品模型。

## 阶段与验收

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 1 | 配置兼容、连接、GORM 模型及版本迁移 | 真实 MySQL 有表、无外键、唯一键和 CHECK 有效；测试账号标记可持久化；拒绝接管旧表 |
| 2 | 演示导入、登录／退出、Redis 会话、CSRF、目录／上下文读取 | 所有演示用户有数据库标记；重复导入不覆盖已有数据；HTTP 登录、读取、退出失效；UUID 映射、继承／清空、形成过程和配图保留 |
| 3 | 图、行动、表达、约定、资料、关注、精选写入 | 实库验证事务、版本冲突、幂等重放、跨图／越权拒绝、终点编辑及五个精选；刷新仍存在 |
| 4 | 邮件认证、对象存储、平台 AI 生成、完整前端联调 | 真实依赖可用；浏览器注册／登录、上传、生成、发布和回应走通；关闭 MSW 后无需演示数据回退 |

前两阶段作为第一批可独立运行的交付；其余阶段必须保持待办，不将尚未实现的端点伪装成成功。每阶段补充实际执行命令和结果。

## 演示与旧库

- `backend/etc/config.local.yaml` 作为旧配置输入保留，不输出或提交凭据。通过环境变量选择新 schema，避免对旧库直接迁移。
- 显式管理命令使用 GORM Migrator；迁移状态记录到 schema_versions，业务进程只校验版本。已存在未受本迁移管理的同名业务表时拒绝接管。
- 导入读取当前前端演示导出文件，按固定命名空间将短 ID 映射成 UUID；保存 alias 对照用于旧链接兼容。示例内容不在服务启动时自动重新写入。
- 所有演示作者都建立为带 `is_test_account = true` 的测试用户，不将林岚等示例作者冒充真实用户，也不将所有行动错误归给同一作者。测试数据集另记导入标识。
- 测试号也经过服务端会话。演示登录仅允许显式启用的开发模式及指定测试账号，生产默认关闭；公开资料不暴露邮箱或测试管理字段。
- 集成验证使用独立 schema 和独立 Redis 键前缀，不清空配置里的 Redis，也不修改旧库。测试清理只针对本次明确创建的资源。

### 阶段 3：完成

- 新增图创建／修改／删除、行动发布确认、终点表达／约定修改、资料修改、五个精选及排序、关注设置共九个 POST 接口。所有写入校验会话及 CSRF，事务内再次验证认证版本。
- 创建命令的业务事实和幂等回执同事务提交，重复请求重放原始结果；修改采用 expectedVersion。图内所有写入共用图锁，采用 READ COMMITTED 避免等待锁之前的旧快照污染检查。
- 发布只确认服务端生成，不接受浏览器直接提交的标题、事实文稿或伪造 AI 对话。真实生成接口尚待第四阶段；本阶段集成测试只使用标记明确的服务端生成夹具。
- 保留现有终点整理规则，不增加原作者专属限制；实际整理者与原行动者分别记录。引用只按主要来源继承表达／约定，合入只补事实背景，继承空值、明确清空及四类约定状态得到保留。
- 精选固定具体分支节点、最多五个、数组排序；校验本人分支及有效表达归属，清空、归属改变和删除后过滤不可用记录，不自动移到新下游。

- 测试在引用写入阶段主动注入失败，验证之前写入的节点、编号和生成确认不会残留，使用同一提交键重试可成功。

## 阶段 4 的接入顺序

1. 对象存储与上传：参考 `32b82cd0^` 的 `infrastructure/storage/tencent_cos.go` 调用方式，使用独立版本前缀；识别实际 MIME、尺寸和大小，持久化资产状态，返回资产 UUID 及展示地址。补齐资料／图 DTO 的资产身份，前端替换 data URL 写入。嵌入演示资源与云端资源按明确的对象键归属读取，不能在云存储失败时回退演示图片。
2. 平台 AI 与生成用例：参考旧 `infrastructure/ai/provider_client.go` 的请求方式，平台配置默认模型和密钥，服务端组装引用背景、文档草稿和对话。网络调用在数据库事务之外，pending 记录、实际输入清单、来源快照和成功输出分段落库，确认继续采用第三阶段用例。必须补充多用户整理时的私有输入隔离：后续操作者只能使用已确认历史及自己的未确认输入，不能因为共享节点对话而公开他人草稿；现有连续性校验也要同步适配实际采用的消息清单。
3. 邮件注册与密码重置：参考旧 `infrastructure/mail/tencent_ses.go`，模板变量沿用验证码和有效分钟数；验证码、频率限制和消耗操作放入隔离 Redis 键空间，密码哈希及认证版本事务更新。真实邮件验收使用明确指定的测试收件地址，不能向演示邮箱发送。普通注册不接收测试账号管理标记。
4. 前端联调：处理匿名访问、真实登录／退出、CSRF、401 和账号切换缓存；逐项迁移生成确认及资产 DTO，关闭 MSW 后验证注册、上传、生成、发布、回应和刷新读取。保留已有 hash 参数，检查旧短 ID 链接在 UUID 目录下的定位，草稿账号／图／来源身份迁移也需明确处理；不能只验证新建 UUID 链接。

本阶段外部客户端均由 bootstrap 创建并注入，不恢复旧版计划、协作或个人 AI Key 业务。验收分别记录真实邮件、云存储、AI 和浏览器结果，测试夹具不能代替这些外部验证。
